0 Get the files and FileZilla

If you are reading this on your Pi, you have probably already cloned the repository. If not, open a terminal and run:

cd ~
git clone https://github.com/Harper-EF12/iot-web-intro.git
cd iot-web-intro
ls

You should see:

  • server/: the files that will go onto your website
  • pi/: the Python script that stays on the Pi
  • tutorial.html: this page

Then install FileZilla, the program you'll use to copy files to your website:

sudo apt update
sudo apt install -y filezilla

Set up FileZilla once

  1. Open FileZilla from the menu (Internet → FileZilla), or type filezilla & in the terminal.
  2. Go to File → Site Manager → New site and name it piN.
  3. Fill in the General tab:
    • Protocol: FTP
    • Host: the FTP host from your slip. Port: 21
    • Encryption: Only use plain FTP (insecure)
    • Logon Type: Normal. User and Password: from your slip
  4. Click Connect. If FileZilla warns about an insecure FTP connection, click OK. That warning is accurate, and we'll come back to why in Step 8.

FileZilla has two sides:

  • Left (Local site): your Pi. Navigate to /home/your-username/iot-web-intro/server.
  • Right (Remote site): your website's folder on the server. It may be empty, or contain a placeholder page from the hosting company.
Only upload the files each step names

Upload files one at a time, from inside the server folder. Never drag the whole iot-web-intro folder across. It contains a hidden .git folder and your Pi's config, and anything you put on the server can be downloaded by anyone.

1 Hello world: a plain HTML page

Open index.html in nano and put your name where it says YOUR NAME HERE:

cd ~/iot-web-intro/server
nano index.html

Save with Ctrl+O, Enter, then exit with Ctrl+X.

In FileZilla, right-click index.html on the left and choose Upload, or drag it to the right-hand side.

Now open your browser at http://piN.mechatron.co.uk/.

Check

You see "Hello world!" with your name. That proves four things work: your FTP login, your folder, your subdomain, and DNS (the system that turns piN.mechatron.co.uk into the server's IP address).

Right-click the page and choose View page source. What you see is exactly the file you uploaded. The server sent it unchanged. Now edit it again, upload it again, and refresh. FileZilla will ask what to do about the existing file: choose Overwrite, and tick Always use this action so it stops asking.

Not changing?

Browsers keep copies of pages. Force a fresh copy with Ctrl+Shift+R.

2 Hello from PHP: code that runs on the server

Upload hello.php, then visit http://piN.mechatron.co.uk/hello.php.

The page shows the server's time, the PHP version, and the public IP address your request came from. Refresh it, and the time changes, because the server builds the page fresh for every request.

Now compare two things:

  1. The file on your Pi: nano hello.php. It is full of PHP code.
  2. View page source in the browser. There is no PHP at all, only the HTML that the code produced.
This is the key idea

Back end code (PHP) runs on the server and can do things the browser can't: talk to a database, keep passwords secret, decide who is allowed to do what. Front end code (HTML, CSS, JavaScript) is sent to the browser and runs there, where anyone can read it. Never put a secret in front-end code.

Try this

Compare Your public IP address on the page with your Pi's own address (run hostname -I in the terminal). Why are they different? (Search for "NAT" if you're not sure.)

Why not call it index.php?

When you visit just piN.mechatron.co.uk/, the server looks for index.html before index.php. If both exist you'd keep seeing the HTML one and think PHP was broken.

3 Connect PHP to your database

PHP needs your database login. Real passwords never go in the shared files, so make your own copy of the template and fill it in:

cd ~/iot-web-intro/server
cp config.example.php config.php
nano config.php

Replace each placeholder with the value from your slip. Keep the quote marks:

config.php
define('DB_HOST', 'your-database-host.example.net');  // host name only, no :3306 on the end
define('DB_NAME', 'your_database_name');
define('DB_USER', 'your_database_user');
define('DB_PASS', 'your_database_password');

define('API_KEY', 'your-api-key');
Two common mistakes
  • The database host is not localhost. The database runs on a different machine from the website. Use exactly what's on your slip.
  • Don't add :3306 to the host. The port is set separately in db.php.

Upload three files: config.php, db.php and db_test.php. Then visit http://piN.mechatron.co.uk/db_test.php.

Check

You see Connected to database … in green, with the database's clock and tables: (none yet). If you see a red error instead, read it carefully, fix config.php, upload it again and refresh. The table in Step 8 explains the usual errors.

What each file does:

  • config.php holds your settings and nothing else. It's the only file you edit.
  • db.php opens the connection. Every other PHP file uses it, so the connection code is written once.
  • db_test.php is a quick health check.
Is config.php safe on the server?

Try visiting piN.mechatron.co.uk/config.php. You get a blank page. The server runs PHP files rather than sending them, and this one runs but prints nothing. That only holds while PHP is working correctly, though. Think about that for your security analysis.

4 The SQL playground: create your table

sql.php runs whatever single SQL statement is written at the top of the file, and shows you the result. To try a statement, you edit the $sql line, save, upload, and refresh. Upload sql.php now and visit http://piN.mechatron.co.uk/sql.php. It starts with SHOW TABLES, which returns 0 rows because the database is empty.

4a. Create the table

Open the file:

nano sql.php

Find the line $sql = "SHOW TABLES";. Put the cursor on it, press Ctrl+K to cut the whole line, then paste this in its place:

sql.php: replaces the $sql line
$sql = "CREATE TABLE readings (
    id          INT UNSIGNED  NOT NULL AUTO_INCREMENT PRIMARY KEY,
    recorded_at DATETIME      NOT NULL,
    temperature DECIMAL(5,2)  NOT NULL,
    humidity    DECIMAL(5,2)  NOT NULL,
    pressure    DECIMAL(6,2)  NOT NULL,
    INDEX idx_recorded_at (recorded_at)
)";

Save, upload sql.php (Overwrite), refresh. You should see Done. 0 row(s) affected. Creating a table changes no rows, so 0 is correct.

What each column is for:

ColumnTypeWhy
idINT UNSIGNED AUTO_INCREMENT PRIMARY KEY A unique number for every row. The database picks it, counting up from 1.
recorded_atDATETIME When the reading arrived, always stored in UTC. The browser converts it to local time for display, so the clocks going back in October can't cause duplicate or missing hours.
temperatureDECIMAL(5,2) Up to 5 digits, 2 after the point: −999.99 to 999.99 °C. Exact decimals, unlike FLOAT.
humidityDECIMAL(5,2)0.00 to 100.00 %RH.
pressureDECIMAL(6,2)Needs one more digit: about 1013.25 hPa.
INDEX idx_recorded_at works like a book's index. It lets the database find "the latest 500 readings" quickly, even when the table holds millions of rows.

4b. Explore

Try each of these in turn. Replace only the text inside the quotes on the $sql line:

see the table's design
$sql = "DESCRIBE readings";
add a test row by hand
$sql = "INSERT INTO readings (recorded_at, temperature, humidity, pressure)
        VALUES (UTC_TIMESTAMP(), 21.5, 55.0, 1013.25)";
see what's in the table
$sql = "SELECT * FROM readings ORDER BY recorded_at DESC LIMIT 20";

Upload and refresh the INSERT twice, then run the SELECT. You have two rows, each with its own id. Refreshing ran the INSERT again. Remember that.

remove a test row (use an id you can see)
$sql = "DELETE FROM readings WHERE id = 1";
Security

Anyone who visits sql.php runs whatever statement is in it at that moment. If you leave a DELETE in there, any visitor deletes data. That's why the SQL lives in the file, and why this script must never be changed to take SQL from the address bar or a form. That would let a stranger type any SQL they liked: a much more extreme version of SQL injection. When you're finished with it, always set it back to a SELECT, or delete it from the server.

5 An API: write and read data with curl

Your Pi shouldn't be editing sql.php. It needs a fixed, safe way to send readings: an API (Application Programming Interface). api.php does two jobs, chosen by the HTTP method:

RequestDoesNeeds the API key?
GET api.phpReturns the latest readings as JSONNo
POST api.phpAdds one reading, sent as JSONYes, in an X-API-Key header

Upload api.php, then open http://piN.mechatron.co.uk/api.php in the browser. That's a GET request, and you'll see your rows as JSON, a text format for structured data that almost every language can read.

5a. Read with curl

curl makes HTTP requests from the terminal, which is exactly what your Python script will do later. -i shows the response headers, including the status code:

curl -i "http://piN.mechatron.co.uk/api.php?limit=5"

The first line should be HTTP/1.1 200 OK. To make the JSON easier to read:

curl -s "http://piN.mechatron.co.uk/api.php?limit=5" | python3 -m json.tool

5b. Write with curl

Replace YOUR_API_KEY with the key from your slip:

curl -i -X POST "http://piN.mechatron.co.uk/api.php" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{"temperature": 21.7, "humidity": 48.0, "pressure": 1009.5}'
Check

You get HTTP/1.1 201 Created and {"status":"stored","id":…}. Run the GET again, or the SELECT in sql.php, and your new row is there. Notice you didn't send a time: the server added it.

5c. Break it on purpose

A server must never trust what it's sent. Send each of these and read the status code and message:

TryChange to the command aboveExpect
Wrong keyX-API-Key: wrong401 Unauthorized
Missing fielddelete "pressure": 1009.5 (and the comma before it)400 Missing field: pressure
Impossible value"temperature": 500400 out of range
Wrong type"temperature": "hot"400 must be a number
Not JSON-d 'hello'400 must be a JSON object
Wrong method-X DELETE405 Method not allowed

Open api.php in nano and find where each of these is checked. Note in particular:

  • prepare() and execute(): a prepared statement sends the SQL and the data separately, so a value can never be run as SQL. This is the standard defence against SQL injection.
  • hash_equals() compares the key in a way that doesn't leak how many characters were right.
  • When the database fails, the API replies 500 Database error and nothing more, so an attacker learns nothing useful.
Put in a few more readings

Run the POST four or five more times with different numbers. You'll want something to chart in the next step.

6 JavaScript charts

Upload chart.html and open http://piN.mechatron.co.uk/chart.html.

You should see the latest values and a chart for each measurement. This page is plain HTML, so the server sends it unchanged. The work happens in your browser:

  1. The browser downloads the Chart.js library from a public CDN (a content delivery network). Nothing was installed on the server.
  2. JavaScript calls fetch('api.php?limit=500'): the same GET you did with curl.
  3. It converts each UTC time to your local time with new Date().
  4. It draws the charts, and repeats every 60 seconds.

Open chart.html in nano and read the <script> section. Things to try:

  • Change REFRESH_SECONDS to 10, upload, then POST a reading with curl and watch it appear.
  • Change a colour in SERIES.
  • Press F12 in the browser, open the Network tab and watch the requests to api.php. You're seeing polling: the browser repeatedly asking for new data.

7 Python on the Pi: send real BME280 readings

Now replace curl with a script that reads the sensor and POSTs a reading every minute.

7a. Check the sensor

i2cdetect -y 1

You should see 77 (or 76) in the grid. If the grid is empty, check the cable, and check that I2C is enabled in Preferences → Control Centre → Interfaces.

7b. Make a virtual environment and install the libraries

A virtual environment (venv) keeps this project's Python libraries separate from the system's.

cd ~/iot-web-intro/pi
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements.txt

Your prompt now starts with (.venv). Whenever you open a new terminal to run the script, cd to this folder and run source .venv/bin/activate again first.

7c. The Pi's own config file

The Python script reads its settings from config.py, alongside it in the same folder. The pattern is the same as the server: copy the template, then fill it in.

cp config.example.py config.py
nano config.py
config.py
SERVER_URL = "http://piN.mechatron.co.uk"
API_KEY = "your-api-key"
INTERVAL = 60
I2C_ADDRESS = 0x77
  • SERVER_URL: your address, with no slash on the end.
  • API_KEY: the same key as in the server's config.php.
  • I2C_ADDRESS: 0x77 or 0x76, whichever i2cdetect showed.

7d. Run it

python upload_bme280.py
Check

Every minute a line appears ending -> 201 {"status":"stored",…}, and chart.html grows. Breathe on the sensor and watch the humidity jump. Stop the script with Ctrl+C.

Read upload_bme280.py. It's short, and does three things in a loop: read, send, wait. Note two details:

  • timeout=10 and the except requests.RequestException mean a dropped network connection prints an error and carries on, instead of crashing the script. But that reading is lost.
  • It sets its own User-Agent. This hosting silently ignores requests that identify themselves as Python's requests library. That was a real problem, found while building this tutorial.
Try this

Unplug the network (or turn off Wi-Fi) for two minutes while the script runs, then reconnect. Look at the output and the chart. What happened, and how could you avoid losing data?

Before you leave

  • Delete db_test.php from the server too. It tells visitors your database name and version.

Questions for your proposal

Use what you've just built to start answering the reading-week questions:

Security: what is exposed?
  • FTP and HTTP both travel as plain text. Your FTP password and your API key cross the network readable by anyone in between. What would HTTPS change? What wouldn't it change?
  • GET api.php needs no key. Anyone who guesses the address can read your data. Does that matter for your project? Does any of the data relate to people (GDPR)?
  • If someone learned your API key, what could they do? How would you notice?
  • Why couldn't chart.html simply include the API key and POST data itself?
Design
  • At one reading a minute, how many rows is that per day? Per year? What happens to the chart if it fetches all of them?
  • The server sets the timestamp. When would you want the Pi to set it instead? (Hint: the network test in Step 7.)
  • The browser polls for new data every 60 s. What are the alternatives (WebSockets, MQTT), and what would they cost you on this hosting?
  • Your project will measure different things. What would your own CREATE TABLE look like, and what ranges would your API accept?
